## Is bringing your own tool right for your work?

You may benefit from bringing a tool to BDC if you:

- Have a script you want to run or reuse across multiple files
- Have a process or analysis that is expected to take several hours
- Need to formalize and scale a multi-step workflow
- Have dependencies that would benefit from containerization
- Want to reuse or integrate an existing Dockerized tool
- Want application versioning

Tools generally need clearly defined inputs, parameters, outputs, dependencies, and computing requirements. Bringing tools into BDC requires familiarity with command-line tools and an understanding of the software, packages, and runtime environment the tool requires.

### **Compatibility Considerations**

Not all tools are immediately compatible. Before getting started, consider:

* **Data compliance and security**: Tools must meet requirements for controlled-access data and secure environments.
* **Licensing**: Tools that depend on proprietary software (for example, MATLAB) or have licensing restrictions are not supported.
* **Interactive tools**: Tools or workflows that rely on interactive inputs or provide interactive visualizations are not typically supported through standard, self-service workflows. These use cases may be supported through dedicated, funded projects within BDC.
* **Containerization**: Tools must be containerizable and describable in supported workflow languages. Thus tools requiring direct hardware access, always-on services, and tools with no defined input are not supported.
* **Nested containers**: Tools that require one Docker container to call or run another Docker container are not supported. Workflows may include multiple tools, with each tool using its own container.
* **Dependencies**: Tools with unavailable or non-portable dependencies are not supported.

## How It Works on BDC-Seven Bridges

At a high level, bringing a tool into BDC-Seven Bridges typically involves:

<ol class="usa-process-list">
  <li class="usa-process-list__item">
    <h4 class="usa-process-list__heading">Identify what you're bringing</h4>
    <p class="margin-top-05">
      Determine whether you are bringing in a tool (single script) or a workflow (multi-step pipeline)
    </p>
  </li>
  <li class="usa-process-list__item">
    <h4 class="usa-process-list__heading">Define your tool’s specifications and container approach</h4>
    <p>
      Clearly define:
    </p>
    <ul>
      <li>Inputs (files required by your application)</li>
      <li>Parameters (any variables required by your application)</li>
      <li>Expected outputs</li>
      <li>Dependencies (libraries, packages)</li>
      <li>Resource requirements (CPU, memory, runtime expectations)</li>
    </ul>
    <p>Determine whether the tool should be Dockerized.</p>
    <ul>
      <li>
        *Consider the number of dependencies, installation and load times, and your familiarity with Docker.*
      </li>
    </ul>
  </li>
  <li class="usa-process-list__item">
    <h4 class="usa-process-list__heading">Test your tool</h4>
    <p>
      Run the tool on sample data
    </p>
    <ul>
      <li>Validate outputs</li>
      <li>Iterate and refine before scaling or combining into workflows</li>
    </ul>
  </li>
  <li class="usa-process-list__item">
    <h4 class="usa-process-list__heading">Use the Tool Creator to create command line tools</h4>
    <p>
      Use the Tool Creator to create command line tools
    </p>
    <ul>
      <li>Reference an open source Docker image or provide your own (for example, via DockerHub or another registry)</li>
      <li>If the Docker image requires credentials/ is not publicly accessible, register the tool using the [BioData Catalyst Image Registry](https://sb-biodatacatalyst.readme.io/docs/the-image-registry)</li>
    </ul>
  </li>
  <li class="usa-process-list__item">
    <h4 class="usa-process-list__heading">Optional: Create a workflow</h4>
    <p>
      Connect tools and data into a reproducible pipeline
    </p>
  </li>
  <li class="usa-process-list__item">
    <h4 class="usa-process-list__heading">Share and scale</h4>
    <p>
      Share with collaborators and run at scale with confidence
    </p>
  </li>
</ol>
